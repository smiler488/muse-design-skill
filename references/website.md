# 从 Muse 迁移到个人网站

把视觉秩序与交互规则迁移到现有网站，不照搬 Muse 的功能布局。

## 改造顺序

1. 识别现有站点结构：技术栈、页面路径、内容数据、导航、语言、暗色模式、搜索与联系方式。保留用户真实内容，记录需要改动的样式与组件。
2. 先统一颜色与文字层级，再调整间距、内容宽度、圆角，最后补充有用的动效。不要用动画掩盖布局问题。
3. 选主页和一个内容页验证长内容及窄屏，再向其余相关页面推广。

## 适配关系

| Muse 的机制 | 个人网站的对应实现 |
|---|---|
| 安静的大背景 | 接近白色的阅读空间，清晰标题和摘要 |
| 小角色承载个性 | 作者头像、原创物件或一张真实研究图片；按需使用 |
| Ideas 内容条目 | 项目/文章列表，配少量缩略图、标题、说明、日期 |
| 浮动胶囊操作 | 简洁的主导航、联系入口或局部筛选；不强制悬浮 |
| 图标交互时显露功能名 | 收藏、外观、布局切换等紧凑工具；悬停/聚焦/触摸显露名称并变化图形，主要导航是否省略文字依可辨识性决定 |
| 逐层活动详情 | 论文摘要→方法/证据→完整页面或原文链接 |
| 稳定的内容＋对话分屏 | 作品目录与详情并列；只有确实需要时才使用 |

## 具体判断

- 主页要让人知道作者是谁、做什么、看什么、怎么联系。保留正常网站导航，不新增假聊天输入框。
- 科研内容优先用可浏览的条目与阅读页；只有独立任务、媒体或操作容器需要卡片。
- 第一屏只突出最主要的动作，如查看研究或联系；其他导航保持安静。
- 内容多时优先过滤、分类、合理摘要；不要只靠把文字变小。
- 原来的品牌色、中文排版、语言切换、URL、搜索、RSS 等按本次要求保留。若没有某功能，不凭空增建。
- 项目名称、履历、论文、统计数据必须来自已有内容或用户提供。样例中的演示内容不能成为个人网站事实。
- 站点已有深色模式时继续兼容；单独设计其语义色对，不能直接反转浅色值。

## 可交给实现智能体的任务例子

“使用 muse-design 改造当前个人网站。先检查仓库，以现有内容和框架为基础，采用浅色中性背景、清晰黑灰排版、克制蓝色动作与柔和浮层。先完成主页和一个项目详情页的本地实现，保留页面路由、语言和所有真实信息。验证移动端、键盘操作和减少动态效果，并列出改动与未验证项。部署按我另外给出的要求执行。”
